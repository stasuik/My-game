# ADR-004 · Дорожный граф и сохранение связей

## Статус

Предложено. Решение подготовлено к ревью техлидом. Реализован запрос соседей и связности по сцене. Формат сохранения приведён как контракт для загрузчика сцены.

## Контекст

Строительство уже соединяет торцы через взаимные ссылки `SnapPoint.ConnectedTo`. При деактивации торца ссылка снимается с обеих сторон. Undo деактивирует построенный объект, а Redo пытается восстановить исходные пары точек через `Connect`. Граф должен отражать эти изменения и позволять пройти от любого сегмента к его соседям. [SnapPoint](../../Assets/SnapPoint.cs) · [SpawnObjectCommand](../../Assets/Scripts/Core/History/SpawnObjectCommand.cs) · [ADR о командах](../architecture/decisions/ADR-003-undo-redo-command-pattern.md)

## Решение

В пределах Unity-сцены используем неориентированный граф. Источник текущей топологии — взаимные соединения торцов.

| Элемент графа | Представление |
|---|---|
| Ребро | Один активный и инициализированный `RoadSegment`. Ребро имеет два конца, `start` и `end`. Мост или переходник с двумя торцами представляется таким же ребром |
| Порт ребра | Торец сегмента с `SnapPoint`. Порт идентифицируется парой «сегмент, роль торца» |
| Узел | Свободный порт образует узел степени 1. Два соединённых порта образуют общий узел степени 2. Узел доступен с обеих сторон стыка |
| Смежность сегментов | Сегменты соседствуют, если у них есть общий узел. Связь `A.end ↔ B.start` возвращает B для A и A для B |

`RoadNetworkGraph` читает связи из готовых сегментов по запросу. `TryGetJunction(segment, end, out junction)` возвращает точку, соседний сегмент и роль его торца. Свободный узел возвращается без соседа. Два сегмента могут соседствовать по обоим торцам. `GetNeighbors(segment)` перечисляет каждый соседний сегмент один раз, а запрос конкретного торца сохраняет различие между двумя стыками.

`AreConnected(from, to)` проверяет достижимость поиском в ширину. Множество посещённых рёбер останавливает обход кольца. Запрос имеет сложность O(V + E) по посещённой компоненте. Активный инициализированный сегмент связан сам с собой. Совпадение координат, касание полотен, выключенная точка или ссылка в другую сцену не создают маршрут.

Строительство и история продолжают работать через `SnapPoint.Connect` и деактивацию. Граф берёт актуальные данные при каждом запросе. После Undo путь через снятую связь исчезает, после успешного Redo возвращается. Если Redo не восстановил одну из связей и откатил объект, связи этой попытки не участвуют в обходе. Превью не инициализирует дорожные торцы и не попадает в граф. Запросы выполняются в основном потоке Unity после завершения строительной операции. [Реализация графа](../../Assets/RoadNetworkGraph.cs) · [Создание сегментов](../../Assets/VRRoadBuilder.cs)

Отдельный индекс смежности потребовал бы синхронизации с Undo/Redo, удалением и загрузкой. Текущий вариант обходит максимум два торца на сегмент. При появлении массовых запросов от трафика можно построить индекс или снимок поверх этой топологии. Правила движения по полосам и узлы с тремя и более подходами потребуют расширения модели. `start` и `end` обозначают геометрические стороны сегмента.

## JSON-контракт связей, версия 1

Блок `roadNetwork` входит в сохранение сцены. Геометрия каждого дорожного сегмента хранится в записи соответствующего объекта сцены, у которой есть `segmentId`. Для динамически созданного сегмента загрузчик сохраняет с геометрией постоянный GUID в формате `D` и восстанавливает его при загрузке. Для заранее размещённого сегмента нужен постоянный ID в данных сцены. Во время Undo/Redo ID существующего сегмента сохраняется. Имена объектов, позиции и Unity Instance ID как ключи не используются.

```json
{
  "roadNetwork": {
    "version": 1,
    "connections": [
      {
        "a": { "segmentId": "2bab98b5-a761-4900-a4f3-193288c8ad23", "end": "end" },
        "b": { "segmentId": "7a0ccc93-37a7-4360-b4b3-c2a5334e3edb", "end": "start" }
      }
    ]
  }
}
```

- Запись `connections` хранит одну неориентированную пару. Зеркальная запись B–A считается дубликатом. Порядок концов в паре не влияет на навигацию. Для стабильного экспорта сортировать концы и записи лексикографически по `segmentId`, затем по `end`. GUID экспортировать строчными буквами.
- Допустимые роли торца — `start` и `end`. Один порт участвует максимум в одной паре. Две связи между одними сегментами допустимы, если используются разные порты. Соединение сегмента с самим собой отклоняется. Свободные торцы восстанавливаются из геометрии сегментов и отсутствуют в `connections`. Для сети без стыков сохраняется пустой массив.
- Сохранение записывает пары из активных взаимных связей одной сцены. Деактивированные Undo сегменты и превью пропускаются. Экспорт и загрузка используют явное соответствие «GUID → сегмент» из данных сохранения.

### Загрузка

1. Проверить версию и форму блока JSON. Неизвестная версия, повторяющиеся ID сегментов, дубли связей и повторное использование порта — ошибки сохранения. Для старого сохранения без `roadNetwork` загрузить геометрию со свободными торцами.
2. Приостановить строительство и историю на время загрузки. Воссоздать сегменты и оба торца, зарегистрировать все GUID. Разрешить ссылки по `segmentId` и роли торца. Проверить, что сегменты принадлежат загружаемой сцене, обе точки свободны и проходят проверку типа и геометрии из `SnapPoint.Connect`.
3. Восстановить пары через `Connect`, чтобы обе стороны стали доступны одновременно. При ошибке удалить собранную копию сети и вернуть сообщение с проблемной парой. Текущую сеть заменять только после успешного восстановления всех пар. Загрузка не добавляет действий в Undo/Redo. После полной замены сцены историю предыдущей сцены сбросить.

Для экспорта и загрузки нужно добавить владельца постоянных GUID и адаптер к будущему сохранению сцены. Текущий граф работает с живыми объектами Unity и доступен независимо от загрузчика.

## Приёмка

- Стык A–B доступен в обоих направлениях. Цепь A–B–C проходима в обе стороны. Изолированный сегмент недостижим из цепи.
- Маршрут по кольцу завершает обход. Undo разрывает путь через удалённый участок, Redo восстанавливает путь только при успешном восстановлении стыков.
- Сохранение и загрузка одной пары восстанавливают обе стороны. Сохранение с отсутствующим ID или повторным использованием порта отклоняется целиком.
