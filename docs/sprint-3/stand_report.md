# ROA-115 — стендовая проверка HistoryStack

Дата: 17.11.2026. Среда: Windows, .NET SDK 9.0.313, консольный тестовый стенд с моделью сцены в памяти.

Источники: [HistoryStack из PR #11](https://github.com/stasuik/My-game/blob/1493759400bd0351b4fa80493546bd79d5fd68b6/Assets/Scripts/Core/History/HistoryStack.cs), [IReversibleCommand из PR #10](https://github.com/stasuik/My-game/blob/647f23bd05ef47699c61077269fd2527c9ecfa00/Assets/Scripts/Core/History/IReversibleCommand.cs).

| Проверка | Фактический результат |
|---|---|
| Пустая история | Оба флага false, счётчики 0, PopUndo/PopRedo возвращают null |
| 55 построек при лимите 50 | Undo идёт от 55 к 6, первые пять объектов остаются, Redo восстанавливает 6–55 по порядку |
| Новое действие после Undo | Старая ветка Redo очищается |
| Clear при заполненных обоих стеках | Оба стека пусты, счётчики и флаги сброшены |
| 1 000 последовательных пар Undo/Redo | Проверены состояние модели сцены и счётчики после каждой пары |

Вывод стенда: **5/5 passed**, код выхода 0. Последовательный прогон проверяет операции стека; ввод с UI, загрузка новой сцены, FPS и память Unity требуют интегрированной сборки.

## Блокер ветки для проверки Unity

В дереве коммита `1493759` из PR #11 нет `IReversibleCommand`, `IHistoryManager` и `RoadActionSnapshot`; код истории их использует. Они лежат в PR #10. Для Unity-прогона нужна ветка с обоими наборами файлов, подключением к сцене и Unity 2022.3.34f1. На проверенной машине в Unity Hub найден Unity 6000.6.8f1. Сам проект в Unity не запускался.

## Замечание к менеджеру по чтению кода

`UndoRedoManager` переносит команду между стеками до выполнения. Если команда вернёт false или бросит исключение, флаги истории всё равно изменятся. При интеграции проверить команду с предсказуемым отказом и согласовать ожидаемое поведение. Например, если команда не изменила сцену, ожидается сохранение её в первоначальном стеке.
