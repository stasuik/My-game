## 1. Геометрия SnapPoint

Работаем в мировых координатах Unity, 1 единица = 1 м, вертикаль `U = (0, 1, 0)`. У каждого торца есть:

- `P` — центр верхней проезжей поверхности торца. Получаем его по геометрии установленной модели с учётом масштаба и смещения. Для дороги и моста сравниваем именно `P.y`. Значения `heightOffset = 0.05` и `0.02` относятся к настройкам размещения их моделей и сами по себе не задают высоту стыка.
- `N` — единичная наружная нормаль плоскости торца, то есть `SnapPoint.Forward`, направленный из сегмента. Для ориентированной оси с касательными `T_start` и `T_end` используем `N_start = -T_start` и `N_end = T_end`. На дуге берём касательную именно в данном торце.
- `type`, `connectedTo`, владелец сегмента — проверяем, что точки активны, свободны, принадлежат разным сегментам и имеют совместимый тип `Roadway`.

Плоскость торца задаётся условием `dot(X - P, N) = 0`. Угол между ненулевыми векторами в градусах:

```text
Angle(v, w) = atan2(length(cross(normalize(v), normalize(w))),
                    dot(normalize(v), normalize(w))) × 180/π
```

В формулах с углом сначала проверяем `lengthSquared(v), lengthSquared(w) > 1e-6`, как в проверке осей SnapPoint. Для стыка сравниваем `N_A` с `-N_B`, так что идеальные торцы имеют ошибку 0°. Подмена ошибки стыка углом между двумя наружными нормалями меняет ожидаемое значение на 180°. [SnapPoint](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/SnapPoint.cs) · [RoadSegment](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/RoadSegment.cs)

## 2. Захват, подвод и условие фиксации

| Проверка | Формула | Константа |
|---|---|---|
| Магнит для подвижного торца `Q` | `lengthSquared(P - Q) <= r²` | `r = clamp(snapRadius, 0.50, 1.00)` м, по умолчанию 0.75 м |
| Поиск лучом из `O` по единичному `D` | `t = dot(P - O, D)`. Кандидат в пределах дальности при `0 < t <= reach` и `lengthSquared(P - O - tD) <= r²` | Тот же радиус. Меньше отклонение от луча — выше приоритет, при равенстве выбирается меньший `t` |
| Подвод при продолжении от выбранного торца | Для ненулевого вектора протягивания `V` проверка `Angle(V, N_A) <= maxSnapTurnAngle` | 30° по умолчанию. В этом режиме прямой пролёт выравнивается по `N_A`, а при превышении угла построение блокируется |
| Положение после выравнивания | `lengthSquared(P_A - P_B) <= 0.001²` | 0.001 м в 3D, поэтому разность высот тоже не превышает 1 мм |
| Направление после выравнивания | `lengthSquared(N_A + N_B) <= 0.001²` | `2 × asin(0.001/2) × 180/π ≈ 0.0572958°` |
| Подгонка кромки после успешной проверки стыка | Вершины у плоскости торца проецируются на неё, затем ищется ближайшая вершина ответной кромки | 0.005 м. Это допуск геометрии сетки |

Для поиска по расстоянию выбираем ближайший допустимый торец. В кандидаты проходят только свободные совместимые точки. Для второго конца прямой дороги дополнительно проверяем направление по общей оси и поперечное отклонение точки от оси в пределах 1 мм. Предлагаемое правило для точной ничьей — сравнить стабильный ID точки, чтобы результат не зависел от порядка обхода. При фиксации повторно проверяем обе точки и геометрию. Если проверка не проходит, возвращаем причину и не меняем связи или сцену. [Поиск и допуск подвода](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/VRRoadBuilder.cs) · [Ограничение дальнего торца](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/VRConstructionController.cs#L418)

## 3. Допустимый радиус и угол изгиба

Для поворота на одном уровне `L` — длина центральной линии дуги, `n` — число полос, `w` — ширина одной полосы в метрах, рассчитанная по габаритам модели методом `GetLaneWidth`. `W = n × w` — ширина полотна. При `w <= 0` дугу строить нельзя.

```text
L ∈ [2, 30] м, n ∈ {1, 2, 3}
R_min     = max(0.75 × W, 0.01 м)
θ_max_rad = min(π/2, L/R_min)
θ_max_deg = θ_max_rad × 180/π
R         = L/abs(θ_rad)
R_inner   = R - W/2 >= W/4
```

Угол ограничивается симметрично влево и вправо. При `abs(θ_deg) < 0.5°` используется прямая, радиус не вычисляется. Для соответствия текущему жесту: `θ_request_deg = sign(x) × max(0, abs(x) - 0.08) × 180`, где `x` — боковое смещение руки в метрах, а коэффициент имеет единицу град/м. На отпускании свободную длину округляем до 0.1 м и пересчитываем предел угла по итоговой длине. Допуск на шве из раздела 2 проверяется по касательной готовой дуги, поэтому угол изгиба может быть значительно больше угла ошибки стыка.

При условной ширине полосы **3.0 м** получаются следующие предельные углы. Проект берёт фактическую ширину из префаба.

| Полосы | Минимальный радиус оси | При L = 2 м | При L = 5 м | При L = 10 м |
|---:|---:|---:|---:|---:|
| 1 | 2.25 м | 50.93° | 90.00° | 90.00° |
| 2 | 4.50 м | 25.46° | 63.66° | 90.00° |
| 3 | 6.75 м | 16.98° | 42.44° | 84.88° |

Для горизонтального начала `P₀`, единичной касательной `F` и `B = normalize(cross(U, F))` точка центра дуги на расстоянии `s` вдоль оси задаётся через `k = θ_rad/L` и `φ = k × s`:

```text
P(s) = P₀ + (F × sin φ + B × (1 - cos φ)) / k
T(s) = F × cos φ + B × sin φ
N_start = -F
N_end   = T(L)
```

Для прямой: `P(s) = P₀ + s × F`, `T(s) = F`. Для первой реализации дуга имеет свободный выход. Кривой переход между двумя произвольно заданными торцами требует отдельного решения и проверки радиуса вдоль всей траектории. [RoadArc](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/RoadArc.cs) · [Ограничение угла в контроллере](https://github.com/stasuik/My-game/blob/993c61068bf698074435be81c82d71e71931b228/Assets/VRConstructionController.cs#L388)

## 4. Мост, отметки и аппарели

**Прямой стык.** При строительстве моста от дороги выровнять верх настила по отметке торца дороги. При продолжении дороги от моста применить то же правило в обратную сторону. Для двух уже размещённых торцов прямой стык проходит только по итоговым допускам раздела 2. Если `abs(Δh) > 0.001 м`, где `Δh = P_B.y - P_A.y`, прямую фиксацию между этими торцами отклоняем. Если разность высот не больше 1 мм, всё равно проверяем полную 3D-дистанцию и нормали.

**Аппарель для разных высот.** Предлагаемые игровые параметры первой реализации — прямой план, горизонтальные касательные на входе и выходе в пределах допуска стыка, равная ширина проезжей части на обоих торцах в пределах 1 мм, максимальный продольный уклон `g_max = 0.10` (10%, около 5.71°), горизонтальная длина `D ∈ [2, 30]` м. Подъём и спуск рассчитываются одинаково через модуль перепада. Для двух подходов к мосту расчёт выполняется отдельно по каждому берегу.

```text
H = (P_B.x - P_A.x, 0, P_B.z - P_A.z)
D = length(H)
F = H/D
u = s/D, 0 <= s <= D
P(s) = P_A + s × F + Δh × (3u² - 2u³) × U

grade(s) = dy/ds = (Δh/D) × 6u(1-u)
grade_peak = 1.5 × abs(Δh)/D              # при u = 0.5
D_required = max(2 м, 1.5 × abs(Δh)/0.10)
Δh_max(D)  = 0.10 × D / 1.5
```

Концы профиля совпадают с заданными точками, а уклон в обоих концах равен нулю. Производная по горизонтальной дистанции задаёт касательную для сетки и коллизии: `T(s) = normalize(F + grade(s) × U)`. На первом конце аппарели наружная нормаль равна `-F`, на втором — `+F`. Поэтому нормаль существующего начала должна совпасть с `+F`, а нормаль существующего выхода — с `-F`, с угловым допуском из раздела 2. Если длины места недостаточно, хотя бы один торец смотрит в сторону или отличается по ширине, этот вариант аппарели блокируется. Совпадение отметок на подходе само по себе не заменяет проверку габаритов. Проверь объём полотна на пересечение с препятствиями и соседними сегментами по всей длине. Разрешён контакт по двум стыковым кромкам, а не взаимное проникновение полотен. Превью и фиксация используют один набор проверок.

| Перепад высот | Минимальная горизонтальная длина |
|---:|---:|
| ±0.50 м | 7.50 м |
| ±1.00 м | 15.00 м |
| ±2.00 м | 30.00 м |
| ±2.10 м | 31.50 м, превышает лимит |

Значения 10% и 2–30 м для аппарели — предлагаемые лимиты проекта. В `main` есть прямой пролёт и выравнивание торцов. Генерацию такого профиля предстоит реализовать. ## Проверочные случаи для реализации

- При радиусе 0.75 м цель на 0.750 м захватывается, цель на 0.751 м — нет. Занятая ближайшая точка пропускается в пользу следующей допустимой.
- Подвод 29° и 30° проходит проверку выравнивания, 31° — блокируется. После выравнивания ошибка торцевых нормалей 0.05° допустима, 0.06° — нет. Разность центров 1.0 мм допустима, 1.1 мм — нет.
- При ширине 9 м и длине 2 м запрос изгиба в 30° ограничивается до 16.98°. Внутренний радиус при предельном изгибе составляет 2.25 м.
- При соосных горизонтальных торцах перепад ±1 м допускается на 15 м и отклоняется на 14.99 м. Перепад 2.1 м отклоняется даже на 30 м. Для обоих знаков высоты проверить совпадение кромок и отсутствие ступеньки.
- При пересечении аппарели с препятствием, потере точки между превью и подтверждением или занятости торца операция не оставляет частично созданной геометрии либо связи.
