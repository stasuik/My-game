# Спецификация структуры снимка состояния сцены

**Статус** — контракт для реализации и передачи Стасу. Описывает целевой формат снимков Undo/Redo. Текущий `RoadActionSnapshot` в `dev` хранит идентификаторы соседних объектов без ролей торцов и содержит изменяемый массив. Код в этой задаче не меняется. [Текущая структура](../../Assets/Scripts/Core/History/RoadActionSnapshot.cs)

## 1. Границы снимка

`RoadActionSnapshot` — плоский снимок затронутой части сцены. Команда хранит `actionType`, общий набор затронутых объектов и торцов, а также два независимых состояния `before` и `after`. Операции создания, удаления, перемещения, изменения параметров и стыковки используют один контракт.

- В состоянии есть только данные объектов, которые действие создаёт, удаляет или меняет. Отсутствие записи в `objects` означает отсутствие объекта в этом состоянии **только для ID из общего набора `affectedObjectIds`**. Например, у спавна объект присутствует только в `after`, у удаления — только в `before`.
- `affectedPorts` содержит торцы, которые действие может освободить, занять или перестроить. Это объединение затронутых торцов для `before` и `after`, включая обе стороны меняющихся связей и все соединения объектов, которые будут пересозданы или чья геометрия меняется. `connections` перечисляет все связи этого набора в конкретном состоянии. Торец из `affectedPorts`, которого нет ни в одной паре состояния, свободен. Связи остальных торцов сохраняются.
- Внешний сосед представлен только ID и ролью торца. Если его геометрия и параметры сохраняются, снимок его объекта не нужен. Для изменения топологии без правки объектов `objects` может быть пустым с обеих сторон.

Структура хранит числа, перечисления, идентификаторы и массивы записей. Все связи выражены ключами. Внутри снимка отсутствуют ссылки на `GameObject`, `Transform`, `SnapPoint`, `RoadSegment`, префабы, материалы, Mesh, Collider и другие экземпляры Unity. Цикл дорожной сети остаётся набором пар ID. [ADR дорожного графа](../adr/ADR-004-road-network-graph.md) · [Требования Undo/Redo](sp-undo-redo-ux.md)

## 2. Состав записи объекта

| Поле | Тип в памяти | Правило |
|---|---|---|
| `objectId` | `Guid` | Обязательно. Постоянный идентификатор экземпляра. Для дороги равен `segmentId` из ADR-004. Сохраняется при Undo, Redo и загрузке |
| `kind` | `enum : byte` | Обязательно. Определяет способ восстановления: `prop`, `straightRoad`, `bridge`, `roadArc` |
| `assetId` | компактный ключ каталога `uint` | Обязательно. Разрешается через реестр типов и префабов. В JSON записывается устойчивый текстовый ключ каталога, а не локальный номер, путь или отображаемое имя |
| `position` | три `float`, метры | Обязательно. Координаты в пространстве родителя, у корневого объекта — координаты сцены |
| `rotation` | четыре `float`, нормализованный кватернион | Обязательно. Порядок компонентов x, y, z, w. Пространство совпадает с `position` |
| `scale` | три `float` | Обязательно. Локальный масштаб по осям |
| `parentId` | опциональный `Guid` | Только при наличии логического родителя, влияющего на позу или группировку. Родитель разрешается через реестр объектов сцены. Цикл в цепочке родителей считается ошибкой |
| `road` | небольшая структура значений | Для дороги и моста хранит `laneCount` и параметры построения, от которых зависит восстановление. Для дуги обязательны `lengthMeters`, `angleDegrees` (со знаком) и `laneWidthMeters`. Для других видов способ восстановления задан ниже |

Обычный объект восстанавливается из каталога и позы. Прямой дорожный сегмент и мост восстанавливаются из каталога, позы, масштаба и полосности. Привязочные точки берутся из геометрии и правил инициализации соответствующего вида. Если использован параметр, который нельзя однозначно восстановить из этих данных, генератор сохраняет его значением в `road`. Например, при индивидуально изменённых торцах сохраняются записи `startLocal` и `endLocal`, каждая с локальным `position` и единичной наружной `normal`. Поле `lengthMeters` для прямого полотна требуется только для генератора, которому недостаточно масштаба и каталога. Дуга строится заново по параметрам, без копирования сетки. [Генератор дуги](../../Assets/RoadArc.cs) · [Торцы сегмента](../../Assets/RoadSegment.cs)

`actionType` находится в команде. Время записи можно добавить к диагностике команды, если оно понадобится для профилирования. Для восстановления сцены время не требуется.

## 3. Метаданные стыков и восстановление

Торец — пара `{ segmentId: Guid, end: Start | End }`. Стык — одна неориентированная пара торцов `{ a, b }`. Роли `start` и `end` сохраняются явно. Два сегмента могут иметь два разных стыка, если использованы четыре разных торца. Зеркальные записи одного стыка и повторное использование одного торца недопустимы.

1. Разрешить все ID и проверить исходное состояние затронутых торцов. Если реальный стык отличается от ожидаемого исходного, операция завершается отказом. Это защищает созданный позже стык с внешней дорогой.
2. Подготовить целевые объекты, позу и параметры. Инициализировать торцы до восстановления топологии. Проверить принадлежность одной сцене, совместимость, доступность после снятия затронутых связей и совпадение торцов по действующим допускам.
3. Применить геометрию и восстановить каждую пару через `SnapPoint.Connect`. Если операция прерывается, восстановить исходные объекты и их пары. История переносит команду между стеками только после полного успеха. Для реализации понадобится применяющий метод, который сообщает об отказе менеджеру. ## 4. Копирование и сериализация

**В истории Unity** снимок хранится в памяти. Записи объектов и стыков — структуры значений, массивы принадлежат снимку. При захвате данные из временных списков копируются в новые компактные массивы. После регистрации команда отдаёт массивы только через интерфейс, который не даёт их менять или получить изменяемую ссылку. Присваивание структуры, внутри которой находится массив, копирует ссылку на массив. Глубокое копирование требуется на границе захвата и при выдаче изменяемой копии. Для пустых коллекций используется общий пустой массив. JSON на пути Undo/Redo не создаётся.

**На границе экспорта** использовать версионированный JSON UTF-8 и отдельный DTO с полями, пригодными для `JsonUtility`. DTO меняет `Guid` на строку формата `D` в нижнем регистре, числовой ключ каталога — на стабильный `assetId`, роли торцов — на `start` и `end`. Позы записываются объектами с компонентами. В прикладных данных выбор вида управляет чтением параметров `road`. Отсутствующий `parentId` обозначает корневой объект. Пустые массивы сериализуются как `[]`. Строковые значения `actionType` — `createRoad`, `deleteRoad`, `transformRoad`, `modifyRoadProperties`, `connectSnapPoints` и `disconnectSnapPoints`. Валидатор проверяет версию, обязательные поля, конечность чисел, норму кватерниона, известные виды, ссылки и уникальность портов. Порядок пар нормализуется по ADR-004. Формат оболочки действия предназначен для диагностики и тестов. Сохранение сцены по ADR-004 хранит состояние графа без стека Undo/Redo.

Пример экспортируемого действия. A уже существует, а B добавляется. ID A фигурирует только в затронутом порте и паре связи.

```json
{
  "version": 1,
  "actionType": "createRoad",
  "affectedObjectIds": ["2bab98b5-a761-4900-a4f3-193288c8ad23"],
  "affectedPorts": [
    { "segmentId": "2bab98b5-a761-4900-a4f3-193288c8ad23", "end": "start" },
    { "segmentId": "7a0ccc93-37a7-4360-b4b3-c2a5334e3edb", "end": "end" }
  ],
  "before": { "objects": [], "connections": [] },
  "after": {
    "objects": [
      {
        "objectId": "2bab98b5-a761-4900-a4f3-193288c8ad23",
        "kind": "straightRoad",
        "assetId": "road.straight.default",
        "position": { "x": 6, "y": 0.05, "z": 4 },
        "rotation": { "x": 0, "y": 0, "z": 0, "w": 1 },
        "scale": { "x": 1, "y": 1, "z": 2 },
        "road": { "laneCount": 1 }
      }
    ],
    "connections": [
      {
        "a": { "segmentId": "2bab98b5-a761-4900-a4f3-193288c8ad23", "end": "start" },
        "b": { "segmentId": "7a0ccc93-37a7-4360-b4b3-c2a5334e3edb", "end": "end" }
      }
    ]
  }
}
```

Объём снимка растёт пропорционально числу изменённых объектов и затронутых стыков. Оценка полезных данных одной связи — **34 байта** при двух 16-байтных GUID и двух однобайтовых ролях, без выравнивания, массивов и накладных расходов CLR. Проверять фактические аллокации нужно в Unity Profiler на одиночном размещении и на цепочке. Память объектов, которые существующая команда спавна держит выключенными для Redo, учитывается отдельно.

## 5. Передача в разработку

Стасу на реализацию передаётся контракт из трёх частей: реестр постоянных ID и каталога, независимый захват состояний с точными парами торцов, восстановление с отказом и откатом при конфликте. Минимальный тест приёмки — снять состояние для A–B, изменить временный список после захвата, восстановить стык и проверить пару с обеих сторон. Затем заблокировать один торец и убедиться, что сохранены исходная топология и стек истории. Экспортный тест должен отклонять неизвестную версию и порт, занятый в двух парах.
