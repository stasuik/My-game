# Спецификация PBR-материалов, 3D-эффекта Dissolve и продуктовой телеметрии Undo/Redo

## 1. Контекст и цели спринта
В рамках Спринта 3 (Шаг 6) реализуются три взаимосвязанных компонента визуализации, оптимизации и продуктовой аналитики:
1. **Настройка PBR-материалов и оптимизация геометрии VR-панели** (`VRPanelPBROptimizer`): обеспечение реалистичного микрорельефа, шероховатости (Roughness/Smoothness) и металличности (Metallic) интерфейса в VR с поддержкой Single-Pass Instanced рендеринга и GPU Instancing для удержания стабильных 72–90 FPS на автономных шлемах (Meta Quest 2/3).
2. **3D-эффект плавного растворения и сборки объекта** (`VRDissolvePBR.shader`, `VRDissolveEffect`, `DissolvableSpawnCommand`): устранение резких визуальных скачков и «поппинга» геометрии при отмене/повторе создания объектов; использование шейдерного cut-out с горящей кромкой (эмиссионный контур: янтарный при Undo, лазурный при Redo).
3. **Продуктовая телеметрия и аналитика событий Undo/Redo** (`UndoRedoTelemetryManager`): сквозной сбор событий взаимодействия пользователя со стеком истории для выявления фрустраций, частоты ошибочных действий и оптимизации глубины стека.

## 2. Спецификация PBR-материалов и VR-оптимизации

### 2.1. Физические свойства поверхностей (PBR)
- **Корпус панели инструментов:**
  - Albedo: Темный графит `#1F2129` (sRGB: `0.12, 0.13, 0.16`).
  - Metallic: `0.85` (матовый конструкционный алюминий).
  - Smoothness: `0.65` (легкий микрорельеф без ослепляющих бликов в шлеме).
- **Интерактивные 3D-кнопки (Undo / Redo):**
  - Metallic: `0.70`, Smoothness: `0.75`.
  - Динамическая подсветка: эмиссионный ореол при наведении лазера (`#3399FF`, Emission Intensity `1.5`).

### 2.2. Бюджет производительности геометрии и отрисовки
- **Общее число полигонов панели (LOD0):** не более 2,400 треугольников.
- **Количество Draw Calls:** не более 4–6 DC на весь UI-блок за счет статического батчинга и включения `enableInstancing = true` на общих PBR-материалах.
- **Время кадра:** UI и эффект растворения должны укладываться в **< 0.8 мс** на GPU Quest 2.

## 3. 3D-эффект растворения (VR Dissolve FX)

### 3.1. Механика работы шейдера `Custom/VRDissolvePBR`
- Шейдер использует текстуру процедурного шума (Perlin / Simplex Noise) либо мировые координаты вершины для генерации карты отсечения `clip(noise - _DissolveAmount)`.
- При граничных значениях порога формируется горящая эмиссионная кромка (`_EdgeWidth = 0.05`), подсвечиваемая HDR-цветом:
  - **Undo (Исчезновение):** Оранжево-янтарное свечение (`#FF5A1A`), символизирующее деконструкцию объекта.
  - **Redo (Восстановление):** Голубое голографическое свечение (`#26BFFF`), символизирующее материализацию объекта.
- Длительность перехода: **0.25 с** (250 мс) с S-образной кривой сглаживания `AnimationCurve.EaseInOut(0, 0, 1, 1)`.

## 4. Продуктовые метрики и события телеметрии

### 4.1. Схема событий телеметрии (`UndoRedoTelemetryManager`)

| Имя события | Триггер | Ключевые параметры payload | Назначение аналитики |
| :--- | :--- | :--- | :--- |
| `undo_triggered` | Пользователь нажал кнопку Undo или хоткей Ctrl+Z | `actionName`, `undoStackSize`, `redoStackSize`, `executionDurationMs` | Оценка востребованности отмены конкретных типов дорожных блоков |
| `redo_triggered` | Пользователь нажал кнопку Redo или хоткей Ctrl+Y | `actionName`, `undoStackSize`, `redoStackSize`, `executionDurationMs` | Оценка частоты возврата действий (понимание, была ли отмена случайной) |
| `undo_failed_empty_stack` | Попытка отмены при пустом стеке | `timestamp`, `sessionDuration` | Выявление ложных кликов и непонимания состояния интерфейса игроком |
| `redo_failed_empty_stack` | Попытка повтора при отсутствии отмененных действий | `timestamp`, `sessionDuration` | Анализ эргономики индикаторов доступности Redo |
| `stack_capacity_eviction` | Вытеснение старейшей записи при переполнении стека (> 50) | `evictedAction`, `currentCapacity` | Контроль достаточности лимита глубины истории |

### 4.2. Ключевые продуктовые метрики (KPI)
1. **Undo-to-Build Ratio:** Отношение числа отмен к общему числу размещенных секций дорог (норма: 8–14%). Значения > 25% сигнализируют о проблемах с автостыковкой (Snapping) или неудобном контроллере.
2. **Accidental Undo Rate (Redo immediately after Undo):** Доля случаев, когда в течение 3 секунд после Undo следует Redo (норма: < 5%). Высокий процент указывает на случайные нажатия курков.
3. **Empty Stack Frustration Index:** Частота повторных нажатий Undo/Redo при пустом стеке (> 2 кликов подряд). Сигнализирует о незаметности блокировки кнопки.

## 5. Интеграция с Continuous Integration (CI)

- Автоматический запуск тестов NUnit в headless-режиме Unity (`-runTests -testPlatform EditMode`).
- Сбор метрик покрытия кода (Code Coverage) и публикация артефактов тестов в GitHub Actions.
- Контроль нулевого уровня предупреждений компиляции при PR.
